# 日报/周报/工作总结生成器

快速生成结构化的工作汇报内容，包括日报、周报、月度总结和年终述职报告。核心原则：数据量化成果、突出个人贡献、体现业务价值。

## 触发词

`日报` | `周报` | `月报` | `工作总结` | `述职报告`

## 报告类型

### 日报
- **用途**: 记录每日工作进展，同步团队信息
- **篇幅**: 200-500字
- **频率**: 每个工作日
- **核心**: 今日完成 + 明日计划 + 问题&风险

### 周报
- **用途**: 总结一周工作，展示阶段性成果
- **篇幅**: 500-1500字
- **频率**: 每周五/周一
- **核心**: 本周成果 + 下周计划 + 数据指标 + 风险预警

### 月度总结
- **用途**: 回顾月度OKR/KPI完成情况
- **篇幅**: 1000-3000字
- **频率**: 每月底
- **核心**: 目标完成度 + 关键成果 + 经验复盘 + 下月规划

### 年终述职
- **用途**: 全年工作回顾，个人价值展示，晋升依据
- **篇幅**: 3000-8000字（或PPT 15-30页）
- **频率**: 年底/年初
- **核心**: 年度成果 + 业务贡献 + 个人成长 + 未来规划

## 日报模板

```markdown

1. 【项目A】完成XX功能开发，已提交代码评审
   - 具体说明：实现了XX模块，涉及XX接口
   - 进度：该功能整体完成80%
2. 【项目B】与XX部门对齐需求，确认XX方案
   - 结论：采用方案二，预计周三完成
3. 【日常】处理XX工单3个，平均响应时间15分钟

## 明日计划 📋
1. 【项目A】完成剩余20%开发 + 单元测试
2. 【项目B】输出技术方案文档v1

## 问题&风险 ⚠️
```

## 周报模板

```markdown
# 周报 | MM.DD - MM.DD | 姓名 | 部门

## 本周概要
> 一句话总结本周最重要的成果

## 关键成果 🎯

### 项目A：XX功能上线
- **状态**: ✅ 已完成 / 🟡 进行中 / 🔴 有风险
- **本周进展**:
  - 完成XX模块开发及测试（代码量约2000行）
  - 通过QA验收，0 P0/P1 bug
  - 灰度发布至5%用户，数据表现正常
- **关键数据**:
  - 性能提升：接口响应时间从800ms降至200ms（提升75%）
  - 用户反馈：灰度期间无负面反馈
- **下周计划**: 扩大灰度至50%，观察3天后全量

### 项目B：XX需求调研
- **状态**: 🟡 进行中
- **本周进展**:
  - 完成5位用户访谈，整理用户需求清单
  - 输出竞品分析报告v1
- **下周计划**: 完成需求文档PRD，组织评审会

### 日常工作
- 处理工单12个，平均响应时间8分钟（SLA目标15分钟）
- 参加会议4次，输出会议纪要2份
- Code Review 5次，指出问题8处

## 数据指标 📊
| 指标 | 目标值 | 本周实际 | 趋势 |
|------|--------|----------|------|
| 需求交付 | 3个 | 3个 | ✅ 达标 |
| Bug率 | <2% | 1.5% | ✅ 达标 |
| 响应时间 | <15min | 8min | ✅ 优于目标 |

## 下周计划 📋
1. 【P0】项目A全量发布 + 监控
2. 【P1】项目B需求评审 + 技术方案
3. 【P2】团队分享：XX技术主题

## 风险&问题 ⚠️
1. 项目A全量发布依赖运维排期，需提前确认时间窗口
2. 项目C需求变更频繁，建议组织需求冻结会议

## 本周感悟/建议 💡
（可选：对团队/流程/工具的建议）
```

## 数据量化技巧

### 量化公式

| 原始表述 | 量化后 |
|----------|--------|
| 完成了很多需求 | 完成需求12个，超额完成20% |
| 提升了系统性能 | 接口响应时间从2s降至500ms，提升75% |
| 减少了Bug | Bug率从5%降至1.2%，下降76% |
| 节省了时间 | 自动化流程节省人工3人天/周 |
| 推动了项目上线 | 协调5个团队，按时完成交付（原计划30天，实际28天） |

### 没有直接数据时的量化方法

1. **时间维度**: "从XX天缩短到XX天"
2. **频率维度**: "从每周X次优化到每月X次"
3. **规模维度**: "覆盖XX用户/XX个业务线"
4. **对比维度**: "相比上季度提升XX%"
5. **效率维度**: "相当于节省X个人力"

## 格式规范

### 通用原则
1. **结构清晰**: 使用标题、列表、表格，一目了然
2. **数据先行**: 用数字说话，避免"很多""大量"等模糊词
3. **结果导向**: 先说结果再说过程
4. **简洁有力**: 日报不超过500字，周报不超过1500字
5. **风险前置**: 问题和风险要主动暴露，不要藏着

### 状态标记
```
✅ 已完成    🟡 进行中    🔴 有风险/延期    ⏸ 暂停
```

### 优先级标记
```
【P0】紧急且重要    【P1】重要不紧急    【P2】一般优先级
```

## 使用示例

### 写日报
```
今天做了这些事：1. 改了登录页面的bug 2. 开了产品评审会 3. 写了个自动化脚本，帮我写成日报格式
```

### 写周报
```
这周主要做了用户系统重构，完成了80%，下周继续。还处理了10个工单。帮我写一份周报，要有数据量化
```

### 写月度总结
```
这个月主要做了3个项目：A项目上线了、B项目在做、C项目刚启动。OKR完成了90%。帮我写月度总结
```

### 写述职报告
```
今年我主导了核心系统的微服务改造，带了3个人的小组，还做了2次全公司技术分享。帮我写年终述职大纲
```

## 注意事项

- 日报/周报保持一致的格式，方便主管快速浏览
- 量化数据要真实可验证，不要虚报
- 风险和问题要及时暴露，不要等到出事才说
- 述职报告的核心是"证明你的价值"，每一条都要有据可依
- 不同公司/团队的模板可能不同，以团队实际要求为准
- 如果不确定某个数据，标注"约"或"预估"
