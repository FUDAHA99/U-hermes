U-Hermes 使用说明
================================================================


一、这是什么
----------------------------------------------------------------
一个装在 U 盘里的 AI 智能体。

它和网页版聊天机器人不一样：它能在这台电脑上读写文件、执行命令、
按计划自动做事。所有配置和聊天记录都留在 U 盘里，不上传到任何服务器。

它不自带 AI 能力，需要你自己的模型密钥（见第二节）。


二、开始之前：你需要一个 API 密钥
----------------------------------------------------------------
U-Hermes 调用你选定的模型服务商。先去其中一家注册、充值，拿到密钥：

    DeepSeek    platform.deepseek.com            便宜，写代码强
    Kimi        platform.moonshot.cn             长文本
    智谱 GLM    open.bigmodel.cn                 有免费额度
    通义千问    dashscope.console.aliyun.com     有免费额度
    MiniMax     platform.minimaxi.com            语音、多模态
    火山豆包    console.volcengine.com

这些服务都是按用量收费的（多数送少量免费额度）。没有密钥，
U-Hermes 一个字也答不出来 —— 这一步没有办法跳过。


三、启动
----------------------------------------------------------------
1. 双击  Windows-Start.bat
2. 第一次启动会自动弹出配置页面：
     选服务商 → 粘贴密钥 → 点「测试连接」→ 通过后点「保存配置」
   「测试连接」是真的去请求了一次模型，通过就说明能用。
3. 回到黑色窗口按任意键，浏览器会在界面就绪后自动打开。

第一次启动要联网下载一次网页界面，大约 1-3 分钟，之后就不用了。


四、不工作的时候
----------------------------------------------------------------
双击  Windows-Menu.bat ，选  [6] 一键诊断。

它会挨个检查网络、密钥、余额、端口，并用中文说明下一步该做什么。
遇到问题先跑它，比自己猜快得多。

常见情况：
  · 提示「余额不足」      —— 去服务商官网充值，密钥本身没问题
  · 提示「密钥无效」      —— 多半是复制时带了空格，重新粘一次
  · 浏览器打不开界面      —— 换个浏览器，或手动访问 127.0.0.1:8648
  · 安装网页界面失败      —— 网络问题，换个网络或挂代理后重试


五、网页界面的登录密码
----------------------------------------------------------------
网页界面出厂时账号是「无主」的：谁第一个用 admin / 123456 登录，账号
就归谁——而登录页会把这组默认密码直接印在上面给所有人看。

U-Hermes 做了两件事来堵住它：

  1. 界面只监听本机（127.0.0.1），局域网里的其他人打不开；
  2. 第一次启动时自动把账号占下来，换成一个只属于这份 U 盘的密码。

那个密码会打印在启动时的黑色窗口里，同时存在：
    data\webui\登录密码.txt
换电脑登录也是同一个。想换成自己好记的：登录后进入 设置 -> 账户。

这件事值得认真对待：这个界面背后的智能体能在这台电脑上读写文件、
执行命令，不是一个普通的聊天网页。


六、你的数据在哪
----------------------------------------------------------------
  配置和密钥    U 盘上的  data\  文件夹
  聊天记录      data\state.db   （只增不减，占满 U 盘时用菜单 [7] 清理）
  配置备份      data\backups\   （每次保存配置前自动留一份）
  工作区        默认是安装目录旁边的「U-Hermes工作区」文件夹，
                智能体读写文件都在这里，升级不会动它。
                想换个位置：配置页面第 3 项「智能体工作区」。
                注意这是默认位置，不是围栏 —— 你在对话里写明完整
                路径时，它照样能读写别处。

运行期间，为了让 AI 引擎读到配置，会在本机的
    C:\Users\<你的用户名>\.hermes\
放两个文件：config.yaml 和 .env（里面有你的 API 密钥）。
按 Ctrl+C，在「终止批处理操作吗(Y/N)?」时选 N，会删掉这两个文件；
选 Y 等于直接结束脚本，清理就轮不到执行了。下次在这台电脑上启动时
也会先清理上一次的残留。

如果是直接点窗口 X 关掉、或者强制关机，这两个文件会留在那台电脑上。
在别人的电脑上用完，请打开 Windows-Menu.bat 选 [8] 清理本机残留。

说明白一点：U-Hermes 只往那个文件夹放这两个文件，也只删这两个。
那个文件夹里如果还有别的东西，是那台电脑自己装过的 Hermes 留下的，
我们不会动它——[8] 会告诉你还剩几项，要不要删由你决定。


七、停止和带走
----------------------------------------------------------------
在黑色窗口里按 Ctrl+C。它会问「终止批处理操作吗(Y/N)?」——选 N。
听起来反了，但这个问题问的是「要不要把脚本一起掐掉」，选 N 才会让脚本
把本机上的配置副本清理干净。选 Y 或者直接点 X 关窗口也能停掉服务，
只是清理留到下次启动，或者用菜单 [8]（见上一节）。

拔 U 盘之前请先停掉它。

全新安装是安全的：数据库运行在 DELETE 日志模式，每提交一条就直接落盘，
中途断电或拔盘不会丢掉已经完成的消息。正在生成回复的那一条可能会丢，
所以不要在它还在打字的时候拔。

**如果你是从旧版本升级过来的，先看第八节最后一段。** 老的数据库可能还在
WAL 模式，那种情况下拔盘的风险要高得多。


八、升级
----------------------------------------------------------------
从 https://github.com/FUDAHA99/U-hermes/releases 下载新压缩包，然后：

  1. 先关掉正在运行的 U-Hermes
  2. 直接解压到当前目录，选「替换目标中的文件」

配置、密钥、聊天记录和登录密码都在 data\ 里，新压缩包不会覆盖它们
（压缩包里的默认配置叫 config.yaml.default，只有第一次启动、你还没有
配置时才会被用到）。

如果你想更稳妥一点，也可以解压到一个新文件夹，再把旧目录的整个 data\ 复制进去，确认能正常聊天后再删掉旧的。

升级时有一件事要额外做一次（只有从旧版本升级才需要）：

老版本建出来的数据库可能在 WAL 日志模式。新引擎不会自动把它改回来——
在有连接打开的情况下改这个会损坏数据库，所以它宁可保持原样，只在
data\logs\errors.log 里记一条错误。而 WAL 模式在 U 盘上被拔掉的风险
明显更高。

判断方法：如果 data\ 里有 state.db-wal 这个文件，就是还在 WAL 模式。

改回来（**先把整个 data 文件夹复制一份备份**，并确认 U-Hermes 完全关闭）：

    cd 到 U-Hermes 目录，然后逐个执行
    hermes\.venv\Scripts\python.exe -c "import sqlite3;c=sqlite3.connect(r'data\state.db');print(c.execute('PRAGMA journal_mode=DELETE').fetchone());c.close()"

对 data\response_store.db 和 data\kanban.db 重复一次（存在的话）。
看到输出 ('delete',) 就成功了，之后 -wal 和 -shm 文件会消失。


九、不想要了
----------------------------------------------------------------
删掉整个 U-Hermes 文件夹，程序就没了。但有三样东西不在里面：

  1. 你的工作区
     在安装目录**旁边**（默认叫「U-Hermes工作区」），不在里面。
     升级不动它，删安装目录也不动它 —— 你自己的文件都在这儿，
     确认不要了再单独删。每次启动时窗口里会打印它的位置。

  2. 用过的每台电脑上的配置副本
     就是第六节说的那两个文件（config.yaml 和 .env，里面有密钥）。
     按第七节的方式退出会删掉；没删掉的用菜单 [8] 清理本机残留。

  3. 旧版本留下的下载缓存
     旧版本装网页界面时，npm 和 uv 会把缓存放在本机的
         %LOCALAPPDATA%\npm-cache
         %LOCALAPPDATA%\uv\cache
     这两个文件夹是那台电脑上所有 Node / Python 项目共用的，
     所以我们不替你删。确定那台电脑用不上就整个删掉，
     或者执行 npm cache clean --force 和 uv cache clean。
     新版本已经改成放在 U 盘里：npm 那份装完就自动删掉，uv 那份留在
     U 盘的 .uv-cache 文件夹里（一百多 MB，不想要可以手动删，
     删了下次装东西会重新下载）。

我们不写注册表、不装服务、不改系统 PATH。
