# U-Hermes 招聘版使用说明

招聘版为 HR 提供四项任务：生成 JD、简历打分排序、生成面试题、候选人问答。默认使用 `deepseek-flash`，需填写客户自己的 DeepSeek API Key。首次打开预置的是虚构公司“青禾智选”和演示 JD；正式使用前请换成自己公司的资料。

## 一、启动招聘版

1. 将包含招聘版的 Windows 便携包完整解压到电脑或 U 盘。不要在压缩软件内直接运行。
2. 双击包内的 **`Windows-Recruit.bat`**。从源码使用时，这个文件在 `portable/` 中；请先按项目说明准备运行环境。
3. 保持启动窗口打开，等待浏览器打开 **`http://127.0.0.1:8648`**。看到“招聘工作台”即进入招聘版。浏览器没有打开时，可手动输入该地址。
4. 使用完后先复制需要的结果，在启动窗口按 Ctrl+C，等待程序退出后再关闭窗口，最后安全弹出 U 盘。

通用版仍通过 `Windows-Start.bat` 启动。两个版本默认都使用 8648 端口，切换时先关闭当前版本的启动窗口，再打开另一个。招聘版使用独立配置，不改动通用版的模型、密钥或聊天记录。

## 二、填公司资料和 API Key

1. 点击右上角 **“公司与用量设置”**。
2. 登录 [DeepSeek 开放平台](https://platform.deepseek.com/) 创建本公司的 API Key，在 **“DeepSeek API Key”** 中填写；这不是 DeepSeek 聊天网页的登录密码。模型保留 `deepseek-flash`。模型名和价格以客户账号实际可用的服务为准；不可用时请管理员确认，不会自动改用更贵的模型。
3. 在 **“公司资料”** 中替换虚构资料，建议保留以下栏目：

   - 公司名称、业务介绍。
   - 每个在招岗位的名称、人数、薪资范围及发薪月数。
   - 上下班时间、午休、休息日、工作地点；居家办公如有条件，请写清适用岗位。
   - 福利、试用期、招聘流程、HR 联系方式。

4. 不确定的内容写“待 HR 确认”，不要填成已确定的承诺。保持岗位薪资、地点与 JD 一致。
5. 检查月度上限，点击 **“保存设置”**。保存后即可使用。

密钥保存后不会回显，输入框留空会保留原密钥；填写新 Key 可以替换。公司资料也可在首次启动后用记事本编辑 `data/recruit/company-info.md`，保存为 UTF-8。请修改 `data/recruit/` 中的客户配置，包内 `recruit/` 是出厂演示资料。

## 三、日常使用

### 1. 生成 JD

选择 **“生成 JD”**，填写岗位及职责要求，例如：

> 请写一份新媒体运营 JD，小红书 / 抖音方向，1 年以上经验优先，也欢迎有作品的优秀应届生。负责内容策划、账号运营、达人合作和数据复盘。薪资、工作时间和福利按公司资料填写。

点击 **“生成 JD”**。查看右侧结果，核对薪资、职责、福利及“待 HR 确认”的事项。确认后点击结果下方 **“用作当前 JD”**，它会进入简历打分页。也可展开 **“当前 JD”**，直接粘贴本公司已有的正式 JD。

生成的 JD 不会自动发布，也不会自动覆盖公司资料。

### 2. 简历打分与排序

1. 选择 **“简历打分”**，检查“当前 JD”是否为本次招聘岗位。
2. 点击文件选择按钮，可一次选择多份简历。支持文字 PDF、扫描 PDF、文字与扫描页混合的 PDF、DOCX、UTF-8 TXT / MD，以及 JPG / JPEG / PNG / WEBP / BMP 图片。
3. 等待读取完成。PDF 逐页先读取文字，文字不足的页才进行本地 OCR；图片和照片也在本机识别。页面会显示读取或扫描件识别中的状态，低配置电脑和多页文件需要更久。
4. 展开 **“预览 / 校正简历文字”**（OCR 简历默认展开），核对姓名、工作年限、公司、技能和业绩数字，必要时直接校正文字。修改自动用于本次评分，无需另按保存；原文件不变。尤其要检查数字、小数点、分栏顺序和遗漏内容，再勾选本次要处理的候选人。
5. 每次最多 5 份，每份不超过 5 MiB（约 5 MB），PDF 最多 20 页，图片不超过 2000 万像素、单边不超过 20000 像素，提取文字不超过 2 万字符；需求、JD 和简历正文合计不超过 6 万字符。
6. 填写要求，例如“按当前 JD 逐份打分，写明证据、不足和面试建议，最后按分数排序”，点击 **“打分并排序”**。
7. 查看各候选人的 0–100 分、六维得分、匹配点、不足、需核实问题及排序。复制需要保存的结果。

OCR 默认开启，不需要 Key、不访问云端、不增加模型费用，完整便携包已经带上识别模型，断网也能读取扫描件。只有点击评分等模型任务时，才会把提取后、经 HR 确认的文字交给 DeepSeek。单份文件最多处理 180 秒。OCR 失败、超时或识别文字太少会明确提示；PDF 只要有一页需要识别却失败，整份文件就不会作为成功简历加入，且不计入用量，不会只取其余页继续评分。

手机照片应拍全纸张、尽量正对、保证清晰和均匀光照。程序会尽力处理轻微倾斜和阴影；严重侧拍或横置 90° 的图片请先摆正 / 旋转后上传。严重反光、模糊、遮挡、密集小字、复杂表格或手写内容仍可能出错。失败时请重新拍摄、适当裁剪 / 缩小图片，或请候选人提供 DOCX / 清晰 PDF，不能仅凭不完整识别结果评分。

旧版 `.doc` 暂不支持，请用 Word / WPS **另存为 `.docx` 或 PDF** 后上传；加密 PDF 请先解除密码。演示文件在 `recruit/demo-resumes/`，其中 `06_` 是扫描 PDF，`07_` 是混合 PDF，`08_` 是合成的手机照片风格图片；同名 TXT 备用文件在 `text/` 子目录。所有演示人物、学校、公司及经历均为虚构。

评分只作为辅助建议。缺少信息会标为“简历未体现，待核实”，不能当成候选人没有能力；不要仅凭 AI 分数自动拒绝候选人。最终是否约面、录用由 HR 决定。

### 3. 为选定候选人出面试题

1. 看完排序后，由 HR 确认本次要面试的人。
2. 选择 **“面试题”**；刚才上传的简历仍保留在页面中。取消其他勾选，只选这位候选人的简历。
3. 确认当前 JD，填写面试重点，例如“重点验证内容策划、账号增长数据和本人贡献，生成 30 分钟面试提纲”。
4. 点击 **“生成面试题”**，查看问题、追问方向、考察要点和空白评分表。

工作台需要选择简历后才能生成针对性面试题，不会自动替 HR 选最高分候选人。

### 4. 扮演候选人提问

选择 **“候选人问答”**，输入具体岗位和问题，例如：

> 新媒体运营的薪资是多少？每天几点上下班？双休吗？

点击 **“回答问题”**。回答以已保存的公司资料为依据。资料没有写明的事项会提示转给 HR 确认，并在已有资料中寻找招聘联系方式。工作台不会真的给 HR 发消息或创建工单，需要由使用者自行联系 HR。

公司资料中的薪资、福利等重要条件应由 HR 维护；生成 JD 的草稿不能自动变成新的公司承诺。

## 四、月度上限如何计算

| 任务 | 默认每月上限 | 计算方式 |
| --- | ---: | --- |
| 简历打分 | 300 份 | 一次选 5 份，计 5 份；同一简历再次提交会再次计数 |
| 候选人问答 | 800 次 | 每次提交计 1 次 |
| 生成 JD | 100 次 | 每次提交计 1 次 |
| 面试题 | 100 次 | 每次提交计 1 次 |

页面上方显示本月已用量和上限。“公司与用量设置”中可调整上限，`0` 表示停用该任务。用量按北京时间的自然月统计，新月份使用新额度，历史计数保留。

任务在发给模型前预扣额度。失败、超时或回答不满意也不退还，因为供应商可能已经收费；重试会再次计数。未填 Key、无效上传、请求格式不合要求或超额拦截不会计入用量。单纯上传、文字提取和本地 OCR 均不计打分份数；OCR 失败或超时也不计数。

超限时会显示中文提示，说明已用量、本次所需额度和处理办法。可以减少本次简历数量、下月再用，或请管理员调整上限。用量记录保存在 `data/recruit/usage.sqlite3`，不要删除它来“修复”问题。

这是任务次数上限，**不是固定人民币月费**。实际费用取决于模型价格和输入输出长度。管理员还可在供应商账户中设置可用的消费预算或余额限制；本地默认限制单次输出长度，不自动换模型或追加付费重试。

## 五、数据和权限

- 默认安全模式下，智能体不能执行命令，也不能任意读写电脑文件。简历由程序的受限解析器读取后作为文本交给模型。
- OCR 在本机 CPU 上离线运行，原始图片和扫描 PDF 不发送到云端。点击评分、面试题等模型任务后，提取的简历文字、岗位要求及所需公司资料会发送至 DeepSeek。请使用获准处理的简历，并在演示时使用包内虚构数据。
- 原始上传文件不落盘；当前 JD、已读取简历、输入内容和结果保存在本次页面内存中，刷新或关闭页面会清空，重新打开会载入演示 JD。请先点击 **“复制结果”** 保存需要的内容。
- 处理任务时会在 `data/recruit/runs/` 创建临时处理文件，正常结束会清理；强行关机、拔盘可能留下残留。管理员确认招聘版已停止后可清理该目录。
- Key 以明文保存在本机 `data/recruit/secrets.json`，服务器不会回显它。不要把包含客户 `data/` 的 U 盘内容当成空白模板发给别人。
- 工作台仅监听本机 `127.0.0.1`，适合 HR 在自己电脑使用，也可由 HR 操作演示候选人问答；它不是已对外发布的候选人门户。

OCR 开关由管理员在 `data/recruit/config.json` 中设置：默认 `"ocr_enabled": true`；改成 `false` 后，文字不足的 PDF 页及图片会提示需要开启 OCR 或改用文字版文件。关闭 OCR 不影响每页文字足够的 PDF、DOCX、TXT / MD，网页不能修改该开关。

工具权限开关由管理员在 `data/recruit/config.json` 中控制：默认 `"allow_tools": false`。确有需要时可改为 `true`，下一次请求读取新配置，将允许智能体调用命令和文件工具；这会扩大其对电脑的权限。日常招聘保持 `false` 即可，网页不能修改此开关。招聘版也关闭了插件、MCP 及后台记忆任务。

## 六、常见问题

**启动后看到通用聊天界面，或提示端口占用。** 先关闭正在运行的通用版或另一份招聘版，再双击 `Windows-Recruit.bat`；不要只关浏览器标签页。

**提示缺少运行环境、PDF / OCR 组件或识别模型。** 交由管理员完成便携包安装 / 修复；不要仅复制 `Windows-Recruit.bat`。完整安装会同时安装锁定依赖和离线模型，日常启动不会临时下载。演示时可先使用 `recruit/demo-resumes/text/` 的 TXT 文件；需要说明这次使用的是备用文字。组件版本在 `recruit/requirements.txt` 中锁定。

**为什么有文字的 PDF 仍然需要 OCR？** 系统按页判断：每页文字层至少包含 80 个汉字、字母或数字，才直接使用文字层；不足时会识别整页图片。每次 OCR 结果至少要有 40 个这类字符，空白、标点不计在内。这是防止把页码或零碎文字当成完整简历的最低门槛，并不代表文字已经完整或准确。

**提示 OCR 已关闭、图片过大、文字太少或处理超时。** OCR 关闭时请管理员检查 `data/recruit/config.json` 的 `ocr_enabled`。过大的图片请裁掉背景并缩小；长 PDF 请拆成较短简历。文字太少或模糊时请重新拍摄，或请候选人提供 DOCX / 文字 PDF。这些上传失败不计用量，不能把识别失败当作候选人没有相关经历。

**提示 Key、余额、模型权限或网络问题。** 在设置区重新核对 Key；请管理员检查 DeepSeek 账号和网络。应用不会把供应商完整错误或密钥打印到页面。提交过的任务可能已计数，避免连续点击重试。

**“当前 JD”变回演示岗位。** 刷新页面会清空当前工作内容。请重新粘贴正式 JD；修改公司资料不会自动修改当前 JD。

**结果很长、被截断。** 缩短需求、减少本次简历份数。管理员可在 `config.json` 调整 `max_tokens`，默认 4096、允许 256–8192；更长输出可能增加费用。

## 七、Linux 运行与部署说明（管理员）

业务代码使用相对路径和 Python，未写死 Windows 盘符。准备好与 `versions.env` 一致的隔离 Python 运行环境、锁定版本的 Hermes 引擎及 `recruit/requirements.txt` 依赖后，可在 `portable/` 下运行：

```bash
bash Recruit-Start.sh
```

无需自动打开浏览器或需另选本机端口时，可用该环境的 Python 运行：

```bash
python scripts/recruit-server.py --no-browser --port 8648
```

仓库现有 `setup.sh` 不包含可搬迁的完整 Python，不能将它视作 Linux 免安装便携包。当前引擎锁定在 `v2026.9.24`（0.21.5），要求 Python 低于 3.14；请以 `versions.env` 和 `docs/DEVELOPMENT.md` 为版本依据。服务器模式仍只监听回环地址；公网部署所需的账号、访问控制及 HTTPS 由部署人员另行配置。

演示步骤见 [五分钟演示脚本](RECRUIT-DEMO.md)。
